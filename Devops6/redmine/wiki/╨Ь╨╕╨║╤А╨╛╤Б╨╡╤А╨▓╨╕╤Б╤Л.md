# Микросервисы

[[Wiki|← на главную]]

Каждый микросервис (кроме Factories) публикует Swagger со списком API-методов. Микросервисы разделены на три слоя:

* **DAL** (Data Access Layer) — работа с данными;
* **BLL** (Business Logic Layer, проекты `*.Domain`) — бизнес-логика;
* **PI** (Personal Interface, проекты `*.API`) — контроллеры и потребители сообщений.

## Identity — http://localhost:7001/swagger
Аутентификация пользователей на базе ASP.NET Core Identity: в БД хранятся хэши, а не пароли. В ответ на вход сервис возвращает **JWT-токен**, который затем передаётся в заголовке `Authorization: Bearer {token}` при обращении к остальным сервисам.

Пример ответа на вход:
```json
{
  "succeeded": true,
  "code": 200,
  "result": { "id": "…", "userName": "User", "token": "eyJhbGciOi…" },
  "errors": []
}
```

## Purchases — http://localhost:7002/swagger
Покупки пользователя: просмотр, добавление своих, редактирование.

* **Добавление.** Магазин может добавить покупку без ограничений. Пользователь — только без чека (`"receipt": null`), у таких покупок `IsShopCreate = false`. Параметры `date` и `transactionType` необязательны.
* **Редактирование.** У покупки из магазина пользователь может поменять только способ оплаты `TransactionType` (0 — карта, 1 — наличные). Свою покупку можно менять целиком, включая список товаров; `id` обязателен.

```json
{
  "products": [ { "name": "string", "productId": 0, "cost": 0, "count": 0, "category": "string" } ],
  "date": "2021-03-06T16:58:38.251Z",
  "transactionType": 0
}
```

## Shops — http://localhost:7003/swagger
Магазины, товары и покупки.

* **Покупка товаров** — нужны только `productId` и `count` (не больше, чем есть на складе). При успехе Shops отправляет в Purchases новую покупку с чеком (`receipt`).
* **Поиск по категории** — единственный обязательный параметр `categoryName`, например `{"categoryName": "одежда"}`.

## Factories — http://localhost:7004/
Фоновая служба: каждые 20 секунд отправляет новые товары в Shops согласно данным своей БД.
